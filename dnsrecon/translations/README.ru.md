# Шпаргалка по dnsrecon

[dnsrecon](https://github.com/darkoperator/dnsrecon) — это комплексный инструмент для разведки и подсчета DNS, написанный на Python. Он поддерживает передачу зон (AXFR), обратный поиск, перебор домена, обнаружение записей SRV, обнаружение подстановочных знаков, отслеживание кэша и расширение TLD.

## Основные возможности

- **Тестирование зонной передачи (AXFR):** автоматически проверяет все авторитетные серверы имен на предмет неаутентифицированной зонной передачи.
- **Перечисление записей:** Извлекает записи SOA, NS, A, AAAA, MX, TXT, SPF и SRV.
- **Перебор поддоменов:** Многопоточный поиск по словарю с фильтрацией по подстановочным знакам.
- **Обратное сканирование диапазона IP-адресов:** извлечение записей PTR из произвольных блоков CIDR.
- **Отслеживание кэша:** Проверяет, есть ли на рекурсивных серверах имен определенные домены, кэшированные в памяти.
- **Расширение TLD:** обнаруживает совпадающие домены в национальных и общих доменах верхнего уровня.

## Установка
```bash
# Debian / Ubuntu / Kali Linux
sudo apt-get update && sudo apt-get install -y dnsrecon

# Python pip / pipx
pipx install dnsrecon

# From source
git clone https://github.com/darkoperator/dnsrecon.git
cd dnsrecon
pip install -r requirements.txt

# Verify installation
dnsrecon -h
```

## Стандартное перечисление и передача зон (`-d -t std / axfr`)

### 1. Стандартное перечисление записей DNS
Собирает записи SOA, NS, A, AAAA, MX и TXT и автоматически пытается передать зону для каждого авторитетного NS:
```bash
dnsrecon -d example.com -t std
```
### 2. Только тест передачи выделенной зоны (AXFR)
Тестируйте только уязвимость AXFR на всех авторитетных серверах имен:
```bash
dnsrecon -d example.com -t axfr
```
*В случае успеха вся база данных DNS цели сбрасывается без перебора.*

## Брутфорс поддомена DNS (`-t brt`)

Перебор поддоменов с использованием пользовательских или стандартных списков слов:

### 1. Перебор поддоменов с пользовательским списком слов
```bash
dnsrecon -d example.com -t brt -D /usr/share/wordlists/dnsmap.txt
```
- `-d <domain>`: целевой домен.
- `-t brt`: режим грубой силы.
- `-D <file>`: файл словаря субдомена.

### 2. Брутфорс с фильтрацией по подстановочным знакам
Предотвращает загрязнение результатов конфигурациями DNS с подстановочными знаками (`*.example.com`, разрешающими один универсальный IP-адрес):
```bash
dnsrecon -d example.com -t brt -D /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt --iw
```
- `--iw`: игнорировать результаты разрешения подстановочных знаков.

## Сканирование диапазона обратного просмотра (`-t rvl`)

Перечислите записи PTR для блока IP, чтобы идентифицировать внутренние хосты, почтовые шлюзы и промежуточные экземпляры:
```bash
dnsrecon -r 192.168.1.0/24 -t rvl
```
- `-r <range>`: диапазон IP-адресов в нотации CIDR (например, `192.168.1.0/24`) или в нотации начала и конца (`192.168.1.1-192.168.1.254`).
- `-t rvl`: режим обратного поиска.

---

## Отслеживание кэша DNS (`-t snoop`)

Определите, разрешали ли недавно клиенты в целевой сети определенные домены через свой внутренний преобразователь:
```bash
dnsrecon -t snoop -n 192.168.1.1 -D sensitive_domains.txt
```
- `-n <resolver_ip>`: целевой DNS-сервер для запроса.
- `-D <domains_file>`: список доменов для тестирования (например, конкурентов, вредоносных C2, внутренних порталов).

---

## Ориентация на определенные серверы имен (`-n`)

Запрашивайте внутренние или целевые DNS-серверы напрямую, а не общедоступные восходящие преобразователи:
```bash
# Query the company's internal DNS server directly
dnsrecon -d corp.internal -n 10.10.10.2 -t std
```

## Форматы вывода (CSV, JSON, SQLite, XML)

Сохраните результаты для интеграции с системой обработки заявок, SIEM или дальнейших этапов атаки:

### 1. Экспорт в JSON
```bash
dnsrecon -d example.com -t std --json /tmp/dns_recon.json
```
### 2. Экспорт в базу данных SQLite
```bash
dnsrecon -d example.com -t std --db /tmp/dns_results.sqlite
```
### 3. Экспорт в CSV и XML
```bash
dnsrecon -d example.com -t std --csv /tmp/dns_results.csv --xml /tmp/dns_results.xml
```

## Защитное усиление DNS-серверов

| Уязвимость | Риск эксплуатации | Рекомендуемая защита |
|---|---|---|
| **Неограниченный AXFR** | Полное картирование внутренней инфраструктуры | Ограничить передачу зон только авторизованными IP-адресами вторичного сервера имен (`allow-transfer { 10.0.0.2; };` в BIND). |
| **Открытый рекурсивный преобразователь** | Усиление DNS, DDoS и отслеживание | Отключите внешнюю рекурсию (`recursion no;` в BIND). |
| **Предсказуемые имена хостов** | Поддоменный перебор | Используйте рандомизированные поддомены для чувствительных промежуточных сред. |
| **Захват поддомена** | CNAME указывает на невостребованные сервисы AWS/GitHub/Azure | Проведите аудит оборванных записей DNS CNAME и немедленно удалите неиспользуемые сопоставления. |
